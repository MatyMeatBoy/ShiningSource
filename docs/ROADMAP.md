# Roadmap

Each milestone ends with something that can be checked by a command or seen on
screen. Do them in order; later ones depend on what earlier ones prove.

## M0. The game's C compiles for a PC target (done, 2026-11-12)

Check: `python3 tools/build.py compile` prints `44 of 44 game modules compile`.

- Decomp as a submodule; generated port sources (`build/gen`), decomp untouched.
- Mechanical steps (`PREPARE_STEPS` in `tools/build.py`): ARM register pins,
  empty asm barriers, constant loads written as instructions, literal pool
  directives, the assembler include, assembler names with the platform's C
  prefix.
- Prototypes hoisted where a function is used before the file declares it
  (`games/ss2/port/hoist.json`, generated by `build.py fix`).
- Two source patches with reasons (`games/ss2/port/patches.json`).
- 15 modules replaced by the runtime (`games/ss2/port/modules.json`): the m4a
  sound library and the original toolchain's support library.

## M1. It links and enters the game (done, 2026-11-12)

Check: `python3 tools/link.py` produces `build/dev32/ss2/ss2_dev32.exe`, and
running it with a ROM prints the stubs it reaches.

- 725 absolute symbols: RAM symbols at their GBA addresses, ROM data symbols at
  their cartridge addresses (the ROM file is mapped at `0x08000000`).
- 47 functions stubbed, listed in `build/dev32/ss2/stubs.txt`: 11 BIOS and
  start-up routines, 22 sound entry points, 14 scheduler routines. A stub
  reports its name the first time it runs.
- First run reaches the scheduler (`sub_0800023C`) after `RegisterRamReset`,
  `CpuSet` and the sound initialisation.

## M2. It runs headless (done, 2026-11-12)

Check: `SS_FRAMES=600 build/dev32/ss2/ss2_dev32.exe ROM` prints 600 frame
hashes; `SS_DUMP=400` plus `tools/render_dump.py` shows the language selection
screen.

- Scheduler as native coroutines (`runtime/src/sched.c`), from the 14 routines
  of `asm/sched.s`.
- BIOS calls in C (`runtime/src/bios.c`).
- Frame boundary and interrupt dispatch from the game's own handler table
  (`runtime/src/frame.c`).
- Code pointers in the ROM data rewritten to native functions at load
  (`runtime/src/codeptr.c`; ranges in `games/ss2/port/code_pointer_ranges.json`).
- Flash save in a file (`runtime/src/flash.c`); the SDK flash driver is one more
  module the runtime replaces.
- Crash report with addresses (`runtime/src/dev32_main.c`).

Open from this milestone:

- [ ] Compare the frame hashes with an emulator running the cartridge (the
      port's `make compare`). Needs a script for an emulator that can dump the
      same four memory areas.
- [ ] `ObjAffineSet` uses the C library's sine; replace by the BIOS table so
      every platform computes the same values (required for online).
- [ ] `IntrMain`, `sub_080004B8`, `sub_080004F8`: start-up leftovers and the
      link-cable interrupt routines, stubbed until M7.

## M3. Picture and input (working, 2026-11-12)

Check: run the executable with a ROM; the window shows language selection,
title and character selection, and the keyboard drives the menus.

- Software PPU (`runtime/src/ppu.c`): text and affine backgrounds, regular and
  affine sprites, priorities, windows, alpha blending and fades.
- SDL3 window, integer scaling, keyboard, pacing at 59.7275 Hz
  (`runtime/src/video_sdl.c`). SDL is delay-loaded so the GBA address space is
  reserved first.
- The GBA address space is part of the executable image (`runtime/src/memory.c`):
  asking the system for those addresses at run time is not reliable.
- Scripted input and frame capture for tests (`tools/run.sh`).

Open:

- [ ] Per-scanline effects (registers changed during HBlank): the renderer
      draws whole frames.
- [x] Controller input (SDL gamepad, hot-plug). Remapping comes with the launcher.
- [x] Stability: 32,000 frames of play with random scripted input in the first
      field scene (movement, attacks, the menu ring) without a crash.
- [ ] Calls that rely on ARM register reuse. `tools/check_calls.py` lists calls
      that pass fewer arguments than the function takes; the real ones are
      fixed **in the decompilation** (the ROM still matches with the argument
      written out; first case fixed: `sub_0807A378`). Struct-by-value arguments
      that the ROM passes as separate registers work on 32-bit x86 and must be
      checked again for host64.
- [x] New game reaches the first field scene (frame 9000 of the scripted run).
- [ ] Play further into the game with scripted input and fix what breaks.

What the first playthrough needed, as a guide for what comes next:

- **Stray accesses** (`runtime/src/stray.c`): the cartridge writes through a
  NULL pointer and reads unmapped addresses on the way into the game, and
  divides by zero; the console ignores all three. The fault handler absorbs
  them for game code only and reports each site once.
- **Arguments left in registers**: three calls to the task-creation helper
  passed one argument and relied on the second already being in `r1`. Fixed in
  the decompilation, ROM unchanged. `tools/check_calls.py` and
  `tools/check_decls.py` list the candidates; each real one shows up as a
  crash or a wrong task entry, and `SS_TRACE=1` plus the scheduler's own check
  name the caller.
- **Failed allocations** are reported where they happen
  (`runtime/src/debug_alloc.c`), because the game does not check them.


## M4. Sound and saves (first version working, 2026-11-12)

Check: run with a window and listen; headless, `SS_FRAMES=N` ends with an
`audio:` line (sample frames produced, peak), and `SS_AUDIO_FILE=1` writes
`ss_audio.raw` (48 kHz stereo, 16-bit).

- Native m4a sequencer and mixer (`runtime/src/m4a.c`) reading the song table,
  headers, tracks, voice groups and samples from the ROM; driven once per frame
  by the game's own `m4aSoundMain`; SDL3 audio stream (`runtime/src/video_sdl.c`).
- Flash save file with atomic replace: done in M2.

Open:

- [ ] Compare against the cartridge by ear and by waveform: nobody has listened
      to it yet. Likely differences: envelope timing of the synthesised
      channels, loudness balance between voices, fixed-rate samples.
- [ ] LFO modulation (vibrato, tremolo), reverb, `MEMACC` conditionals.
- [ ] Voice priority and the engine's channel limit (the mixer allows 48 voices
      and steals the oldest).
- [ ] The game reads only the player's status word today; check whether any
      code reads other fields of `MusicPlayerInfo` or the track structures.

## M5. 64-bit (working on Windows, 2026-11-12)

Check: `python3 tools/build_win64.py`, then `build/win64/ss2/ss2_win64.exe ROM`.
The 64-bit build must print the same frame hashes as dev32 for the same
scripted input (`SS_HASH_ALL=1`, compare the two outputs with `diff`).

- The game image (`ss2_game.elf`): the same generated sources compiled for
  x86-64 with 32-bit pointers, with the runtime core and a small C library
  (`runtime/guest/`), linked flat at `0x0A000000`.
- The host (`runtime/host64/`, `ss2_win64.exe`): a 64-bit program linked at a
  low base that carries the whole low address space the game needs (GBA
  regions, the image, its stacks) inside its own image, loads ROM and image, and
  serves a table of services (`runtime/guest/bridge.h`): files, log, video,
  input, sound, coroutine stacks, math. Every service uses the System V
  convention; the image is the same for every operating system.
- Coroutines are the image's own (`runtime/guest/co_x64.S`).
- Struct arguments: adapters are generated where a declaration and the
  definition pass a small struct differently (`tools/abi_thunks.py`; 12
  functions, including typedef and unprototyped forms).
- Locals read before being written are zero on every build
  (`-ftrivial-auto-var-init=zero`).

Result: identical to dev32 for the first **27,082 frames** of the scripted
play-through (new game, then nine minutes of random movement and attacks).

Open:

- [ ] Frame 27,083: an enemy's position differs. The remaining suspects are
      calls that pass fewer arguments than the function takes and rely on what
      an ARM register still held (`tools/check_calls.py`: about 30 functions,
      100 call sites, some of them false positives of the checker). On dev32
      the missing argument is whatever is on the stack, on 64-bit whatever is
      in a register, so both are wrong in different ways. Each one has to be
      resolved from the ROM and written out in the decompilation (the ROM must
      still match), as was done for `sub_08057328` and `sub_0807A378`. This is
      also a requirement for online: every platform must compute the same game.
      Method: SS2Decomp `tools/scripts/try_edit.py` applies a candidate edit only
      if the module object stays identical; six were done on 2026-11-12
      (wrappers that forward their argument, and two calls that take the
      result of the call before them). They did not move frame 27,083. To find
      the cause: `SS_DUMP=27083` on both builds writes `ss_ram_dump.bin`; the
      first differing words are an actor position at `0x02006C74`; `SS_WATCH=
      02006C74 SS_WATCH_FROM=27082` on dev32 names the writer
      (`sub_08013E90`, called from `sub_0801801C`). The inputs of that call
      (speed, direction, the collision check) are the next thing to compare.
- [ ] Linux and Android hosts (the image is already operating-system neutral).
- [ ] The host commits about 220 MB of address space for the arena; most of it
      is never touched. Reduce after the layout settles.

## M6. The port's own features

- Wide view in field scenes; HUD layer that follows and scales with the window.
- Launcher (ROM check, settings, controller mapping, languages).
- Achievements.

## M7. Online

- Acceptance test (owner's requirement, 2026-11-12): four players on different
  continents play a full session without a disconnect. That means the design
  must survive 250 ms+ round trips, jitter and short outages: the game waits
  instead of cutting, a player who drops can rejoin, and no single slow player
  may stall the others indefinitely.
- Transport under `MultiSio`, fixed delay, never-cut rules, state hash.
- Relay process for this game on the VPS; lobby in the launcher.
- Crossplay Windows / Linux / Android.

## M8. Everything else ReKHCoM ships

Web (wasm32), PS5, PS4, Switch, Vita. No online at first. `reloc` mode for the
platforms that cannot map low addresses.
