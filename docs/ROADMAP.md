# Roadmap

Each milestone ends with something that can be checked by a command or seen on
screen. Do them in order; later ones depend on what earlier ones prove.

## M0. The game's C compiles for a PC target (in progress)

Check: `python3 tools/build.py compile` prints `47 of 47 game modules compile`.

State on 2026-11-12: 41 of 47, 8 errors.

- [x] Decomp as a submodule; generated port sources (`build/gen`), decomp untouched.
- [x] Mechanical steps: ARM register pins, empty asm barriers, constant loads
      written as instructions, literal pool directives, assembler include.
- [x] Prototypes hoisted where a function is used before the file declares it
      (`games/ss2/port/hoist.json`, generated by `build.py fix`).
- [x] Three source patches with reasons (`games/ss2/port/patches.json`).
- [ ] 7 "conflicting types": a block-scope declaration disagrees with the
      definition (`sub_080694AC`, `sub_080852CC`, `sub_080009F8`,
      `sub_0809C1B4`, `sub_0809C4E8`, `sub_0809F018`). Fix them **in the
      decompilation** (one prototype per function); the ROM must still match.
- [ ] 1 remaining hand-written ARM instruction sequence.

## M1. It links

Check: a `dev32` executable is produced with no undefined symbols.

- RAM symbols at their GBA addresses (from the decomp's `sym_ram.ld`).
- ROM data symbols at their ROM addresses (from the decomp's data labels).
- Stubs for everything the runtime will provide: BIOS, scheduler, sound engine,
  flash, interrupts. A stub that is called logs its name once.
- The list of undefined symbols is the work list for M2-M4.

## M2. It boots to the first frame, headless

Check: the game runs N frames without a window and writes frame hashes.

- Memory map: EWRAM, IWRAM, I/O, palette, VRAM, OAM, ROM (the user's file).
- Code-pointer table: ROM words that hold function addresses, rewritten to
  native functions at load.
- BIOS in C. Scheduler as native coroutines (read `asm/sched.s` in the decomp:
  14 routines).
- Interrupt delivery at the frame boundary; IWRAM code copies redirected.
- A frame hash over I/O registers, palette, VRAM and OAM, compared with the same
  hashes taken from an emulator running the cartridge: this is the port's
  equivalent of `make compare`.

## M3. Picture

Check: title screen and first field scene match reference screenshots.

- Software PPU: mode 0 backgrounds, sprites, windows, blending, mosaic, affine
  background (the game uses BG2 affine effects).
- SDL3 window, integer/fit scaling, 59.7275 Hz pacing.
- Input: keyboard and controller.

## M4. Sound and saves

- Native m4a sequencer and mixer reading songs from the ROM (the data layout is
  described in SS2Decomp: 400 songs, 676 tracks, 181 samples).
- Flash save file with atomic replace.

## M5. host64

Check: the same game image runs under the 64-bit host on Windows and Linux.

- Game compiled with 32-bit pointers for x86-64 and arm64; flat image; host maps
  the GBA space and serves the call table.
- Android arm64 build with the launcher as first screen.

## M6. The port's own features

- Wide view in field scenes; HUD layer that follows and scales with the window.
- Launcher (ROM check, settings, controller mapping, languages).
- Achievements.

## M7. Online

- Transport under `MultiSio`, fixed delay, never-cut rules, state hash.
- Relay process for this game on the VPS; lobby in the launcher.
- Crossplay Windows / Linux / Android.

## M8. Everything else ReKHCoM ships

Web (wasm32), PS5, PS4, Switch, Vita. No online at first. `reloc` mode for the
platforms that cannot map low addresses.

## Shining Soul 1

Closed until its decompilation exists. When it does: add `games/ss1/decomp`,
run M0 on it, and reuse the runtime.
